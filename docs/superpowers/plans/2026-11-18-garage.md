# Replace MinIO with Garage — Implementation Plan (release 1 and the switch)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release 1 of row 41. Garage runs everywhere, and tests, CI and dev use only Garage. The NUC keeps using MinIO until a one-time switch script (with `--back`) moves it, with every photo checked.

**Architecture:**
- A `garage` service is added beside `minio`. The app's storage address and keys come from compose interpolation, so on the NUC `app.env` decides which store the app uses.
- `scripts/nuc/60-switch-storage.sh` copies through the existing `manage.py photos export | import` path. It refuses unless the source holds every object the database refers to, makes the destination an exact copy, verifies, flips one line, and verifies again through the running app.
- Release 2 (removing MinIO from compose) is a **separate, later plan**. It needs Andrew's OK after backups and a drill pass from Garage.

**Tech Stack:** Docker Compose, `dxflrs/garage:v2.5.0`, Python 3.12 (FastAPI app, click `scripts/manage.py`, boto3), bash (NUC scripts, PATH-shim tests), testcontainers, pytest.

**Spec:** `docs/superpowers/specs/2026-11-18-garage-design.md` (approved by Andrew 2026-11-18).

## Global Constraints

- Image `dxflrs/garage:v2.5.0`, pinned. `docker-compose.yml` is the only place the tag is written.
- Garage command: `/garage server --single-node --default-bucket`. Env:
  - `GARAGE_DEFAULT_ACCESS_KEY: ${S3_ACCESS_KEY…}`
  - `GARAGE_DEFAULT_SECRET_KEY: ${S3_SECRET_KEY…}`
  - `GARAGE_DEFAULT_BUCKET: ${S3_BUCKET_PHOTOS…}`
  - `GARAGE_RPC_SECRET: ${GARAGE_RPC_SECRET…}`
- Secrets: at least 16 characters. Garage refuses to start if the env secret differs from the stored one.
- `deploy/garage/garage.toml` holds no secrets:
  - `db_engine = "sqlite"`, `metadata_fsync = true`, `data_fsync = true`;
  - `compression_level = "none"`;
  - `replication_factor = 1`;
  - `rpc_bind_addr = "[::]:3901"`, `rpc_public_addr = "127.0.0.1:3901"`;
  - `[s3_api]` with `s3_region = "us-east-1"` and `api_bind_addr = "[::]:3900"`;
  - no `[admin]` section.
- Health check `["CMD", "/garage", "status"]`. Volume `garage_data` at `/var/lib/garage`. No published ports on the NUC; dev publishes `127.0.0.1:3900:3900`.
- api, worker and beat take `S3_ENDPOINT_URL` (default `http://garage:3900`), `S3_ACCESS_KEY`, `S3_SECRET_KEY` and `S3_BUCKET_PHOTOS` from interpolation, with the same defaults as Garage. The api has no `depends_on` on any storage service.
- Dev defaults (my call, the builder's to set, as the spec left them): access key `perfectday-dev`, secret `perfectday-dev-secret-0001`, bucket `photos`, RPC secret `0000…` (64 zeros, dev only, never on the NUC).
- `/readyz` names the storage check `storage`.
- Secrets are never printed, logged or committed. Env edits keep the file's mode and owner, write through symlinks to the real file, and leave a `.bak-<timestamp>` copy.
- NUC scripts touch only `perfect-day-*` containers. Never prune or remove Docker images. Never `docker volume rm` anything but what a test created.
- Every script test lives in `scripts/nuc/tests/*.test.sh` or `scripts/tests/*.test.sh` and runs under `make test-scripts`, which is part of `make test-all` and CI's Lint job. Docker and rsync are PATH shims, as in `restore.test.sh`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage explicit paths only.
- `make test-all` after each task touching the API or compose; never at the same time as the dev-stack check.

## Review Focus

1. **A plain `docker compose --profile nuc up -d` after release 1 but before the switch**, which starts Garage with no `GARAGE_RPC_SECRET`. Garage must be able to start, and the app must keep serving from MinIO. `40-update.sh` therefore ensures `GARAGE_RPC_SECRET` before restarting (ruling below), and Task 1's compose test pins "no storage `depends_on`". *(Task 1 test, Task 4 test.)*
2. **The switch interrupted mid-copy** (ssh drop, Ctrl-C, SIGTERM). The app must come back on the source with the env file unchanged. *(Task 5: `trap_restores_source_on_term`.)*
3. **The destination fails to start**, for example Garage refusing because the stored secret differs from `S3_SECRET_KEY`. The switch must stop before stopping the app, say why, and change nothing. *(Task 5: `destination_unhealthy_changes_nothing`.)*
4. **Not enough disk for a second copy.** The switch refuses when free space under Docker's data root is less than twice the source's byte total. *(Task 5: `low_disk_refuses`.)*
5. **Env file variants:**
   - `S3_ENDPOINT_URL` missing (rehearsal env), duplicated, or commented out;
   - the file a symlink;
   - a value containing `=`.

   The flip must set exactly one live line and keep everything else byte-for-byte. *(Task 4: `envfile.test.sh`.)*

**Ruling (plan):** the spec lets only the switch script and `10-secrets.sh` call the "ensure generated setting" helper. Review Focus 1 shows a deploy also needs it, so `40-update.sh` calls it for `GARAGE_RPC_SECRET` too. This fits the spec's "long-term mechanism for any future generated setting". Cost if wrong: one extra idempotent line in the deploy.

### Task 5: The switch script

**Files:**
- Create: `scripts/nuc/60-switch-storage.sh`, `scripts/nuc/tests/switch-storage.test.sh`.

**Interfaces:**
- Consumes:
  - `deploy_lock_take` (`lib/deploy-lock.sh`);
  - `envfile.py get|set|ensure` (Task 4);
  - `manage.py photos export | import --exact`, `photos digest`, `photos missing` and `photos verify` (Task 3);
  - `scripts/nuc/backup-run.sh`;
  - `scripts/smoke-test.sh`.
- Produces:
  - Usage: `sudo ./scripts/nuc/60-switch-storage.sh [--back] [--yes-near-backup]`.
  - Env overrides for the rehearsal and tests (defaults in brackets): `PD_DEPLOY_DIR` [/opt/perfect-day], `PD_ETC` [/etc/perfect-day], `PD_COMPOSE_PROJECT` [none], `PD_COMPOSE_PROFILE` [nuc], `PD_SMOKE_URL` [https://perfectday-api.andrewlass.com], `PD_BACKUP_ROOT` [/var/backups/perfect-day], `PD_RUN_BACKUP` [1], `PD_NOW_HHMM` [current UTC time, for tests].
  - Exit codes:
    - 0: switched;
    - 1: failed, and the app is back on the source, unchanged;
    - 2: refused before changing anything;
    - 75: lock held.
  - Direction: forward is `minio` (`http://minio:9000`, MinIO root keys `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD`, default `minioadmin`) → `garage` (`http://garage:3900`, the `S3_*` keys). `--back` is the reverse.

Steps the script runs, in this order (spec § switch script; each is a named check in the test):
1. Take the lock, else exit 75.
2. Refuse (exit 2) if the endpoint already names the destination. Refuse if within 30 minutes of 02:17 UTC unless `--yes-near-backup`.
3. `ensure GARAGE_RPC_SECRET`. Run `up -d --wait <source> <destination>`; if either is unhealthy, exit 2.
4. Run `photos missing` against the source (one-off api with `-e` overrides for the source endpoint and keys); n > 0 → exit 2. Run `photos digest` on the source; free space under `docker info -f '{{.DockerRootDir}}'` below 2 × bytes → exit 2.
5. Dump the database with `umask 077` to `${PD_BACKUP_ROOT}/pre-switch-<ts>.sql.gz`.
6. Stop api, worker and beat; arm an EXIT/INT/TERM trap that starts them again (on the source) if not yet flipped.
7. Pipe `photos export` (source overrides) into `photos import --exact` (destination overrides). Run `photos digest` on both sides; any difference → exit 1 with a "source vs destination" summary of counts and bytes, never keys. Run `photos verify` with the destination overrides; failure → exit 1.
8. `envfile.py set <PD_ETC>/app.env S3_ENDPOINT_URL <dest url>`. In rehearsal and tests `PD_ETC` points elsewhere. The key values don't change: on the NUC they are the same pair.
9. Start api, worker and beat. Through `compose exec -T api python -c` (urllib to `http://localhost:8000/readyz`), require `checks.storage == "ok"`. Run `photos verify` (live settings), then the smoke test with `SMOKE_CLEANUP=1`. Any failure → set the endpoint back, restart, exit 1.
10. Stop the source service (never `rm`, never `down`).
11. Release the lock; if `PD_RUN_BACKUP=1`, run `backup-run.sh` and report its exit code (it doesn't change the switch's exit code).
12. Print the summary: objects, bytes, deleted, the dump path, the backup result, and `To go back: sudo ./scripts/nuc/60-switch-storage.sh --back` (or, after `--back`, the forward command).
